# 活动文案多语言 Workflow

给 Codex 线程用的共享框架。落地后把本目录推进 git，全组按同一套规矩跑活动文案。

## 这个仓库做什么

每次活动，同事先确认【游戏】，把该游戏的图、时间和道具说明放进 `inbox/`（或直接打在任务里），开一条 Codex 任务说「按活动文案流程跑」。线程会：

1. 锁定游戏，填活动卡，起草中文 Discord / VK / VIP
2. 从中文成稿抽术语，查该游戏语言表后再翻译
3. 导出 Excel；不确定处先出稿并标黄
4. 人确认后，把术语写回该游戏主库

不同游戏的术语、往期、风格、产出互不借用。神器 / 坐骑 / 背饰只写介绍效果，不写数值，不照搬策划原文。

## 目录

| 路径 | 用途 |
|---|---|
| `games.md` | 游戏分类登记表 |
| `inbox/` | 本次活动投放区，一次只放一款游戏的一期，可清空 |
| `glossary/master.csv` | 按游戏隔离的已确认术语 |
| `glossary/<目录名>/lang/` | 该游戏官方语言表（道具名以此为准） |
| `glossary/<目录名>/past/` | 该游戏往期文案资料 |
| `templates/` | 活动卡、Discord、VK、VIP、Excel、黄标骨架 |
| `templates/style/` | 各游戏已提炼风格，文件名为目录名 |
| `outputs/` | 生成结果，按 `outputs/<目录名>/<活动名>/` |
| `skill/SKILL.md` | 给 Codex 线程的操作说明书 |
| `WORKFLOW.md` | 完整流水线（人看、以后做页面也按这个） |
| `prompts/` | 开任务时可用的固定口令 |

## 同事怎么用

1. 从 git 拉下本仓库
2. 用 Codex 打开这个项目
3. 确认游戏已在 `games.md`；新游戏先登记
4. 在 `inbox/notes.md` 写上游戏、时间、新道具、返场；图放进 `inbox/art/`
5. 新建任务，粘贴 `prompts/run-event.md`（聊天里补时间/道具也可以）
6. 到对话里复制 Discord / VK / VIP，到 `outputs/<目录名>/<活动名>/` 拿 Excel
7. 回复黄标结论，让线程更新该游戏主库

每人每个活动开一条新任务，避免串稿。

线程固定顺序：**活动卡 → 中文三套 → 从成稿抽术语查语言表 → 翻译**。不要先翻译空表。

## Git 建议

- 提交：流程文件、模板、游戏登记表、`glossary/master.csv`、各游戏语言表
- 不提交：`inbox/` 大图、`outputs/` 成品（可用 gitkeep 占位）
- 语言表体积较大，有更新时单独提交，方便全组同步查词
- 术语主库有更新时也单独提交

详见 `WORKFLOW.md`。
